# Stage 1 — Research: feed selection, basemap, platform limits

**Date:** 2026-08-28/29 · **Role:** Product Owner · **Status:** complete

Method: every "downloadable" claim below was tested by issuing the HTTP request
from this machine; every feed considered was downloaded and run through the
official MobilityData **gtfs-validator v8.0.1** locally (Java 17). Licenses were
read from the publishers' own pages, not from catalog metadata. Web claims

### Kolkata: a proven negative

- Mobility Database catalog: **zero** entries for Kolkata (code search of
  `MobilityData/mobility-database-catalogs`: 0 hits).
- GitHub holds exactly two Kolkata GTFS repos: `Neelabho/kolkata-bus-gtfs`
  (crowdsourcing scaffold — the `gtfs/` directory contains only `.gitkeep`) and
  `quantum2code/kolkata_gtfs` (one metro line, 25 stops, `agency_url:
  https://fakeurl.com`, calendar expired 2025-12-31).
- WBTC's "smart services" page offers a consumer app (Pathadisha), no data.
  Kolkata Metro is operated by Indian Railways, which publishes no GTFS.
- Logged as the brief requires: **no usable feed; fallback ladder engaged.**

### Delhi: rejected on license, not just staleness

The surprise of this research: Delhi's "Open Transit Data" is **not openly
licensed**. The OTD terms (decoded from the portal's own PDF) reserve all
rights to the Delhi Department of Transport, make permission discretionary and
purpose-scoped, and state that *"modification of any of the Contents or use of
the Contents for any other purpose will be a violation of DoT's copyright."*
Computing isochrones is modification; publishing a compiled artifact in a
public repo is republication. "Free of cost" in the press coverage is about
price, not license. Additional strikes:

- The current static dump sits behind a purpose-disclosure form (name, email,
  usage type, T&C acceptance) — not clicked through; not needed given the
  license verdict.
- OTD's own documentation admits bus stop_times are **synthetic** — "a rough
  estimate generated by assuming a constant speed of travel." An isochrone of
  that would visualize a constant-speed model, not a timetable.
- The only no-signup mirror (transitland archive, commit-pinned URL — the
  branch URL 404s) carries a calendar that expired 2024-01-01, no shapes.txt,
  and 8 duplicate-key validator errors.

### Chennai: selected

`ungalsoththu/ChennaiGTFS` — community-built unified feed covering **MTC bus +
CMRL metro**. 9.1 MB zip, one unauthenticated GET:
`https://raw.githubusercontent.com/ungalsoththu/ChennaiGTFS/main/data/chennai-unified-gtfs.zip`

Why it wins:

1. **It is next in the brief's ladder after Delhi**, and the only candidate
   with an explicit open license: **ODbL**, stated in the repo README —
   share + commercial use permitted, attribution to "UngalSoththu / Ithu Ungal
   Soththu" required, derivatives stay open. (The Mobility Database record
   stamps this feed with Delhi's IIITD terms — that is a **catalog error**;
   the publisher's own statement governs.) A public repo that redistributes a
   compiled timetable artifact needs exactly this.
2. **Its calendar covers today** — the only ladder-order feed that routes
   out of the box. *(Corrected after the stage-3 spike: the calendar holds
   **9 service rows**, windows 2024-05-01 → 2030-05-01 plus a 2026-only
   `weekday` row; only `Regular` (46,973 trips, all days) and `HSC`
   (74 trips, Mon–Sat) carry any trips.)*
3. shapes.txt present; 5,625 stops fits Uint16 indexing with 10× headroom;
   1.36 M stop_times ≈ 1.31 M connections ≈ 18 MB raw artifact (pre-gzip) —
   inside every budget.

Known defects, to be handled in the pipeline and disclosed in the UI/README
(the brief's rule: gaps get logged, never filled):

- **146 malformed rows** (invalid_row_length) + 3 invalid_integer across
  1.36 M stop_times — pipeline skips and counts them; the count ships in the
  build manifest.
- **Provenance is unofficial**: MTC data collected from the MTC mobile app;
  CMRL scraped from its website/PDFs. CMRL schedules are **headway-based**
  (converted to explicit trips by the publisher), and route shapes are
  simplified straight lines (irrelevant to our engine — routing uses
  stop_times, not shapes).
- Internal inconsistency: `feed_info` window closed 2025-12-31 while
  calendar.txt runs to 2030 — publisher extended the calendar without
  updating feed_info. Recorded; calendar.txt governs routing.
- A service literally named `"test "` (trailing space) is active Mon–Wed. The
  stage-3 spike counts its trips; if they are demonstrably bogus they are
  excluded via a config flag with the decision logged in the manifest.
- No suburban rail (MTC + CMRL only) — the UI data note names the covered
  networks.

### Bengaluru: documented runner-up

The best *data* in the set — zero validator errors, freshest calendar
(rebuilt 2026-07, valid to 2027-07), 2.4 M shape points — but
`Vonter/bmtc-gtfs` carries **no license** (GitHub API: `license: null`).
Default copyright means no granted right to redistribute a derivative
artifact. Switching to it is a one-file config change (`config/city.ts`) if
its maintainer ever grants one (contact in feed_info: me@vonter.in) — logged
in NEEDS-HUMAN as optional. Its own README also cautions the source app is
"particularly unreliable for timetables and stop timings."

## 2. Basemap

**Primary: OpenFreeMap public instance** — `https://tiles.openfreemap.org/styles/positron`
(light gray — right under colored isochrone bands; `liberty`/`bright`/`dark`/`fiord`
also available).

- Keyless, no signup, **no request limits**, production/commercial use
  explicitly permitted. Run by Zsolt Ero (MapHub), donation-funded, Cloudflare-
  sponsored CDN. Survived a documented 100k req/s spike (3 B requests/24 h,
  99.4% cache hit) in Aug 2025. No SLA — hence a fallback.
- Attribution: OpenMapTiles + OpenStreetMap mandatory (MapLibre injects it
  from the style); OpenFreeMap credit appreciated.

**Fallback: self-hosted PMTiles extract** of the free Protomaps daily build,
clipped to the Chennai bbox at z0–14 via `pmtiles extract` (ranged reads —
the 120 GB planet is never downloaded). Berlin comparable: ~46×37 km at full
zoom → 84 MB; Chennai at z0–14 estimated 30–80 MB — under Vercel's 100 MB
per-file cap. Served same-origin (no CORS), `pmtiles://` protocol,
`@protomaps/basemaps` style. Range requests on Vercel work in practice
(Accept-Ranges observed; `TOO_MANY_RANGES` exists in their error catalog) but
are not vendor-documented — verify with `curl -H "Range: bytes=0-16383"`
after first deploy before relying on it. Attribution: Protomaps © OSM.

**Tertiary:** isochrones over a plain graticule — the core answer survives a
total basemap outage. (Other keyless options surveyed and rejected: MapLibre
demotiles — no streets; CARTO — keys signposted/raster already gated;
VersaTiles — credible but policy unspecified; MapTiler/Stadia/Jawg — keyed.)

## 3. Vercel Hobby limits (verified against Vercel docs, Aug 2026)

| Limit | Value | Consequence for us |
|---|---|---|
| Static file upload | 100 MB per file | 18 MB artifact fine; PMTiles extract must stay <100 MB |
| Total deployment size | **no documented cap** (15,000 source files max; 32 GB build disk) | non-issue |
| CDN compression | **MIME allowlist — `application/octet-stream` is NOT compressed**; no size gate | `.bin` would ship raw → we ship `.bin.gz` |
| Pre-compressed + `Content-Encoding` | not supported (staff-acknowledged open bug; header stripped on functions) | serve `.gz` as **opaque bytes**, inflate in-browser via `DecompressionStream('gzip')` — no header tricks, no functions |
| Range requests on static | work in practice, undocumented | PMTiles fallback OK; verify on live deploy |
| Bandwidth | 100 GB/mo Fast Data Transfer; overage pauses (no billing), grace window | ~5 MB gz artifact → ~20k cold loads/mo; immutable caching makes repeats ~free |
| Functions (avoided) | Fluid: 300 s max, 2 GB RAM, 250 MB bundle, **4.5 MB response body** | reaffirms static-only serving — the artifact cannot go through a function |
| Builds | 45 min/build, 1 concurrent, 100/day deploys | non-issue |
| Custom headers | `vercel.json` / `next.config` headers on any path incl. static | `Cache-Control: immutable` on hashed artifacts ✓ |
| Plan terms | Hobby is non-commercial/personal use | portfolio project qualifies |

**Engineering consequences adopted:** artifact ships as content-hashed
`timetable.<sha8>.bin.gz` served as an opaque static file; the worker inflates
with native `DecompressionStream('gzip')`; nothing on the hot path touches a
serverless function; all artifact responses carry
`Cache-Control: public, max-age=31536000, immutable`.

## 5. Lighthouse LCP candidacy (platform fact for ADR-007)

Per the Chrome/web.dev definition, LCP considers `<img>` (incl. inside
`<svg>` as `<image>`), `<video>` poster frames, elements with a CSS
`background-image` via `url()`, and text-containing block elements. A
`<canvas>` is **not** an LCP candidate, and neither are inline `<svg>`
shapes — which is why the map canvas can never be trusted to be the LCP
element and the default-view poster must ship as an `<img>`
(fetchpriority=high, explicit dimensions). Source: web.dev/articles/lcp
("What elements are considered?"), checked 2026-08-29.
